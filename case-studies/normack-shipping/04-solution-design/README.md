# Phase 04 — Process & Solution Design

**Case study:** [NorMack Shipping LLC](../README.md)  
**Portfolio status:** Planned — working specification; not a completed client engagement  
**Data classification:** Fictional enterprise and synthetic data only

> **Portfolio note:** This page is a planned phase specification. Activities, findings, solutions and outcomes will be marked complete only after supporting artifacts are produced and validated. No real client contracts, operating results or confidential records are represented.

## Purpose

Turn approved requirements into implementable functional, data, security and integration designs.

## NorMack scenario context

The target operating model must coordinate dispatch, receiving, location/custody, fabrication, billing, and analytics while supporting constrained staffing and exception workflows. Designs are proposals until validated in the scenario.

## Questions this phase will answer

How will data, people, applications and controls interact under normal and exception conditions?

## Work plan

1. Draw TO-BE BPMN maps and explain changed decision points, controls, and responsibilities
2. Write Functional Design Documents (FDD) for shipment lifecycle, inventory/storage movement, crate/pallet work orders, and billing
3. Write Technical Design Documents (TDD) covering application components, environments, integrations, authentication and error handling
4. Develop UML use-case, activity, sequence and component diagrams
5. Develop conceptual/logical/physical ERDs, data dictionaries, key constraints and event schemas
6. Define REST/API interfaces, authorization rules, audit trail requirements, accessibility and performance targets

## Deliverables and evidence checklist

- [ ] TO-BE process maps and functional design (FDD)
- [ ] Technical design (TDD) and architecture decision records
- [ ] UML and ERD diagram set
- [ ] Data dictionary, integration and API specifications
- [ ] Security/access model and nonfunctional requirements

## Completion and review criteria

- All listed deliverables have working links and clear version/status labels.
- Business assertions cite scenario records, analysis or approved assumptions.
- Requirements and technical artifacts use consistent IDs and links to dependent phases.
- Any public dataset uses synthetic records only; no secrets, customer data or company documents.
- Unfinished functionality is labeled **Planned**, **Prototype**, or **Simulation** rather than complete.

**Expected phase outcome:** Reviewable design package with requirements traced to components, screens, entities and test cases.
