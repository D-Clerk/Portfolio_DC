# Phase 06 — Applications & Workflow Automation

**Case study:** [NorMack Shipping LLC](../README.md)  
**Portfolio status:** Planned — working specification; not a completed client engagement  
**Data classification:** Fictional enterprise and synthetic data only

> **Portfolio note:** This page is a planned phase specification. Activities, findings, solutions and outcomes will be marked complete only after supporting artifacts are produced and validated. No real client contracts, operating results or confidential records are represented.

## Purpose

Implement accessible demonstrations that support the validated business processes and show engineering decisions.

## NorMack scenario context

Candidate applications include dispatch/route management, short-term cargo receipt-and-release, work orders for crates and specialty pallets, and a management portal. Native Microsoft platform implementations may need licenses; public demos should be clearly labeled simulations where appropriate.

## Questions this phase will answer

Can a reviewer complete a meaningful business workflow without a paid account or access to confidential systems?

## Work plan

1. Develop a browser-accessible dispatch and shipment-status workflow with exception handling
2. Implement cargo receipt, custody events, storage location assignment and authorized release
3. Implement hybrid crate and specialty pallet quoting, BOM/material usage and assembly status
4. Demonstrate Power Apps/Power Automate or Business Central design concepts with actual platform artifacts where available
5. Build a MERN-based application or limited static simulation using synthetic sample data and safe architecture
6. Document role-based access, validation, automated tests, deployment and operational support

## Deliverables and evidence checklist

- [ ] Live or recorded demo with synthetic seed data
- [ ] Source code and architecture diagrams
- [ ] API contract / screenshots / walkthrough
- [ ] Application test cases and security model
- [ ] Readme documenting live-system vs simulated features and hosting requirements

## Completion and review criteria

- All listed deliverables have working links and clear version/status labels.
- Business assertions cite scenario records, analysis or approved assumptions.
- Requirements and technical artifacts use consistent IDs and links to dependent phases.
- Any public dataset uses synthetic records only; no secrets, customer data or company documents.
- Unfinished functionality is labeled **Planned**, **Prototype**, or **Simulation** rather than complete.

**Expected phase outcome:** Usable demonstrators with explicit functional scope, limitations and implementation evidence.
